# 全量语义审校 — 子代理统一约定

## 工作目录
`D:\fs\workspace\projects\changjiang-youji`

## 审校原则
1. **对照原文判**：每条标注都要能追溯到 `orig`（events/works）里的具体字句，不能凭归纳字段互证
2. **不推衍**：原文没写的不算（如「覺濤瀾洶湧可駭」才算惊叹，光写「江流」不算）
3. **区分声音**：works 的 style/note 里，作者自述 vs 后人评语（沈德潜/林纾/高步瀛等）不能混
4. **存疑不硬判**：拿不准标「存疑」+ 理由，不要为了凑数强行归类

## 输出格式（每个子代理写独立文件）
路径：`data/audit/<切片名>.md`

```markdown
# 审校报告：<切片名>
- 审校对象：<表.字段> <条数>
- 判据：<简述>
- 审校数 / 通过 / 疑似错误 / 存疑：<数字>

## 疑似错误清单
| id | 字段 | 当前值 | 原文依据 | 问题 | 建议 |
|---|---|---|---|---|---|
| ... | ... | ... | 「原文片段」 | 为什么错 | 改成什么/删除 |

## 存疑清单
| id | 字段 | 当前值 | 疑点 | 无法判定的原因 |
|---|---|---|---|---|

## 通过项说明
（简述哪些批量核对通过，如有统计规律写这里）
```

## 纪律
- 只写 `data/audit/<切片名>.md`，不改任何数据文件
- 原文引用用「」括起，必须是 orig 的准确片段
- 报告要给出具体 id，不能只说「有些条有问题」
