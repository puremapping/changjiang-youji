# 数据归档规范

> 每一版数据 = **一个目录**，目录内必含 **方法说明 + 数据文件**。
> 目的：任何时候都能回答「这份数据是怎么来的、能不能信、错在哪」。

---

## 目录结构

```
data/
├── archive/
│   ├── v001_译注原文混排_动词锚定/
│   │   ├── METHOD.md          ← 方法说明（必填）
│   │   ├── data/              ← 数据文件
│   │   │   ├── events.json
│   │   │   └── events.csv
│   │   └── CHANGELOG.md       ← 相对上一版改了什么（v001 可省）
│   ├── v002_纯原文匹配/
│   │   ├── METHOD.md
│   │   ├── data/
│   │   └── CHANGELOG.md
│   └── ...
└── current/                    ← 指向当前采用的版本（软链或复制）
```

**命名规则**：`v{三位序号}_{方法简称}`，序号只增不减。

---

## METHOD.md 必含七项

| 项 | 说明 |
|---|---|
| **1. 版本与日期** | 版本号、生成日期、生成者 |
| **2. 数据来源** | 具体到书名、版本、页码或 URL |
| **3. 处理方法** | 步骤化描述，可复现 |
| **4. 关键判据** | 做了什么判断、依据是什么（尤其是启发式规则） |
| **5. 已知问题** | 明确的错误、不确定处、未覆盖范围 |
| **6. 质量指标** | 条数、覆盖率、抽检结果 |
| **7. 缩写弃用** | 这一版是否被后续版本取代、为什么 |

**判据是重灾区**：任何「我猜的」「按经验判断的」都必须写进去，不能假装是确定规则。

---

## CHANGELOG.md 必含

- 相对上一版：**改了什么方法**、**数据变化多少**、**为什么改**
- 上一版的错误是否修正、修正了几条

---

## 原则

1. **旧版不删。** 出错的方法也是记录——它证明了哪条路走不通。
2. **不掩盖错误。** 已知问题必须写清，不能只写好的。
3. **可复现优先。** 方法描述要让另一个人能重跑出同一份数据。
4. **数字要能对上。** 声明的条数、覆盖率必须是实际算出来的，不是估的。
