# 长江流域五人文选：数据处理两阶段汇报

> 汇报人：项目组
> 日期：2026-11-22
> 说明：本文汇报项目的数据处理工作，分「数据建设」与「数据治理」两个阶段。所有统计数字均从数据文件实测取得，出处标注到文件与字段。

---

## 一、项目与数据范围

本项目对长江流域五位文人的游记作品做信息可视化，五位作者为柳宗元、苏轼、陆游、范成大、张岱，共 17 篇作品。

数据采用两个粒度：

- **事件级（events）**：以「某年某月某日某人到某地做某事」为记录单元，客观可计数，支撑统计与路线还原。
- **篇目级（works）**：以一篇作品为叙事单元，记录处境、主旨、情感、意象、笔法，支撑定性解读。

最终数据规模：

| 数据表 | 条数 | 内容 |
|---|---|---|
| 事件表 events | 266 | 《入蜀记》156 + 《吴船录》110，逐日切分 |
| 篇目表 works | 17 | 柳 9 / 苏 4 / 张 2 / 陆 1 / 范 1 |
| 篇目互文 intertexts | 223 | 事件层 101 + 篇目层 122，每条附原文引文 |
| 地名表 places | 383 | 其中 189 条有现代坐标、194 条如实留空 |
| 人物表 persons | 34 | 五作者 + 同代人物 + 前贤 |
| 编年表 timeline | 34 | 篇目 17 + 生平锚点 15 + 书 2 |
| 文献源表 sources | 6 | 按作者归并的版本与来源 |

## 二、第一阶段：数据建设（从项目转向到 2026-11-22）

**阶段目标：把数据从无到有建起来——解决「有没有、全不全」的问题。**

### 2.1 先定契约，再动手

项目转向后第一件事不是采集，而是确定数据模型：六张表的字段、实体关系、两个粒度的分工全部写入 `SCHEMA.md`，作为后续所有数据工作的共同契约。关键设计决定包括：

- **书与篇分层**：用「父指针 + 文体字段」表达书与篇的关系，不扁平混装。
- **互文必附引文**：Intertexts 每条记录必须附原文引句，不允许只写「提到某人」。
- **游历与写作分离**：works 表用 `visit_*` 与 `write_*` 两组字段，区分「何时游历」与「何时成文」——张岱的金山二篇游于明亡前（1629/1642），成文时间原文未载、据《陶庵梦忆》成书背景推为明亡后追忆（works 表 write 字段因此留空），两者不可混。

### 2.2 文本采集：三层分离

原文与注文严格分开存放，形成三层结构：

- `source/text/`：繁体标点原文（15 篇单篇 + 2 部日记体）
- `source/annotated/`：注释与译注
- `source/merged/`：原文 + 注释合并层（仅 15 篇单篇）

采集策略是「纯文本优先、PDF OCR 兜底」：维基文库等公开权威转录能找到的直接用，扫描版校注本只在必要时局部 OCR。这一策略在实测中避免了大面积 OCR——柳宗元集校注 PDF 的文字层使用私有编码，常规抽取是乱码，纯文本源省去了逐页校对的代价。

**一条铁律在这一阶段确立**：注释里出现的地名不进地名词典，只认原文。第一版数据曾因混入注释地名而作废，这条规则是那次返工的产物。

### 2.3 事件与篇目提取

逐日切分两部日记体：陆游 156 天、范成大 110 天，共 266 个日记日。范成大用干支纪日，逐条按六十甲子换算为序数日，程序自洽校验零误差。期间修复一处真实缺陷：原文「六年閏五月十八日」的闰月月首未被识别，导致其后十条日期挂错月份，修正后条数由 155 确定为 156。

篇目层为 17 篇作品建立处境、主旨、情绪、意象、笔法等定性字段，情绪采用受控词表，不做自由发挥。

### 2.4 基础表与回填

建立 persons、places、sources、timeline 四张基础表，并把事件表与篇目表的外键（人物、地名、文献源）全部回填指向基础表，悬空引用为零。处理了两处一致性问题：

- 同名异地的地名（如「东坡」有黄州与苏州两处）拆为独立实例，避免下游按地名聚合时张冠李戴。
- 存疑人物逐字核原文：原文零出现的条目删除，有实证的补立，生卒无考的一律留空加注，不以常识填充。

### 2.5 阶段成果

数据从无到有，六表齐备、外键连通、生成脚本可复现；项目同期公开至 GitHub（public），完成了隐私审查与版权处理（版权扫描件仅本地查阅，不对外分发）。

## 三、第二阶段：数据治理（2026-11-22 起）

**阶段目标：把已建成的数据审干净、整理好——解决「对不对、信不信」的问题。**

这一阶段由一个问题触发：「数据方面还有没做的事吗」。它把工作重心从「建数据」切换到「治数据」。

### 3.1 溯源追问：补上真正的缺口

在回答这个问题的过程中，对数据来源做了一次完整回溯——互文表的人名词表从何而来、为什么篇目层互文为零、人物表如何建成。回溯暴露出一个结构性缺口：

**篇目表当时没有原文 orig 字段**，只有归纳性的 `style` / `theme` / `note`，因此篇目层互文为零条；此前用归纳字段代替原文做筛选，得到的命中大多是后人评语，不是作品自身的引用。

修正方式是给 17 篇作品补入 `orig` 原文层（全部取自原文文件的连续子串），再按事件层相同的流程从原文重新提取互文，得到 122 条；陶潜、谢灵运、扬雄、司马相如之外的李渤、酈道元、韩世忠三位历史人物按原文实证补入人物表。篇目互文由零变为 122 条，全文互文表达到 223 条。

### 3.2 全量审校：确定性 + 语义双轨

审校采用两条完全不同的轨道，配合使用：

**确定性核对（程序逐条验，100% 覆盖）**：19 项判据，包括原文是否为源文件连续子串、引文是否为对应原文连续子串、外键悬空、坐标范围、id 连续、CSV 与 JSON 一致等。结果全部通过。脚本 `audit_deterministic.py` 可重复运行，报告落 `AUDIT_REPORT.md`。

**语义核对（8 个并行单元全量人工判读）**：对标注类字段逐条对照原文，覆盖活动类型、天气、情绪、景观、意象、篇目归纳字段、互文关系、地名坐标。8 份分片报告 + 1 份总报告留存于 `data/audit/`。

审校结论：找到两类问题——

- **零星硬错误**：如《赤壁赋》「七月既望」被误注为七月十五日（应为十六）、个别引文字形与原文不符、13 条地名坐标张冠李戴（如苏轼黄州赤壁被配到三国赤壁市）。
- **系统性误标**：活动与四维标注由生成脚本的纯子串匹配造成，例如裸「見」被当作交游、「丈人觀」的「觀」被当作游观、日期词头的「月」被当作月象。这类问题根因单一，逐条按报告清单修正。

### 3.3 修复与复验

按「有原文铁证的才改、存疑的不硬改、原文一字不动」的原则组织修复：

| 修复类别 | 数量 |
|---|---|
| 篇目硬错误（日期、字形、评语标来源） | 9 条记录 |
| 地名坐标（有原文与实测双证） | 13 条 |
| 互文关系改判 | 19 条 |
| 无效互文作废 | 1 条（int-066，「山谷間」为地形通名，非人名） |
| 事件活动类型 | 54 条 |
| 事件四维标注 | 69 个字段 |

修复后重跑确定性审计，19 项判据仍全部通过；逐条抽查改动项，均按报告执行。

### 3.4 仓库整理

将并行过程中产生的多份方法说明与工作日志合并为唯一权威文档 `METHOD.md`，原稿与可复现脚本归档至 `data/archive/`，遵循「旧版不删、可追溯」的规范；审校报告与修复记录全部保留。数据目录结构清爽，版本演进完整可查。

### 3.5 阶段成果

数据由「建成了」变为「可核验」：原文与引文 100% 为源文件连续子串、外键悬空为零、每条审校结论有具体 id 与原文依据、每处修复有前后值记录。这一阶段的产出不是新数据，而是**数据的可信度与可追溯性**。

## 四、贯穿两阶段的数据纪律

1. **原文一字不改**：所有 `orig` 为源文本连续子串，程序逐条校验。
2. **查不到就留空**：194 个无现代对应地名保持 null 并注明查证路径，人物生卒无考者留空，绝不估算填充。
3. **错误留痕**：四个历史数据版本全部存档，每版方法文档写明「错在哪、怎么改」；审校与修复报告独立留存。
4. **注释不混入原文**：注释地名、后人评语不作为原文证据使用。
